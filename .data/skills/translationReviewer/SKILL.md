## Before You Start

1. **Say "Using: translationReviewer skill"** at the start of the response.
2. **Read [LEARNED.md](LEARNED.md) first** — project conventions (paths, served languages, TMS, glossary,
   do-not-translate terms) and user preferences override defaults here.
3. **Find the project's own tooling**: grep for `check_translation*`, `*translation*checklist*`,
   `update_translations*`, `.lokalise.yml`, `crowdin.yml`. Run project checkers in addition to this skill's.

## When to Use

1. A PR that updates catalogs from a TMS or adds translations for a feature
2. A backport/forward-port of such a PR (parity check)
3. "This string shows English / the raw key / braces / blank in language X"
4. Auditing locale formatting (numbers, dates, currency) in strings
5. Writing the review as PR comments, a ticket, or a shareable artifact

## Do NOT Use

- Implementing i18n in code (extracting strings, wiring `Intl`) — frontend/backend skill
- Translating new content from scratch — translate directly; use this skill to review the result
- Pure copywriting of the English source — content/UX writing

## Workflow

1. **Scope** — `gh pr view <n> --json title,body,state,baseRefName,headRefOid,files,commits,reviews`;
   fetch the head (`git fetch origin pull/<n>/head:pr-<n>`); note base, merge state, CI, counterpart PRs
   (`gh pr list --state all --search <ticket>`), non-catalog files (tooling, tests), commits after the export.
2. **Mechanical pass** — `<skill>/scripts/validate-catalogs.sh origin/<base> pr-<n> <brand>…` (project
   checker if present + `check_catalogs.py` + `msgfmt -c`). For a merged PR use `<merge>^1 <merge>`. Read ERROR, then WARN, then the TERM SHIFTS
   summary. Add `--all` once to list OLD issues.
3. **Regressions and tooling** — emptied/removed strings, case regressions, `.po` without `.mo`; read
   any export/import script diff like production code ([review-checklist.md](references/review-checklist.md) §8).
4. **Consumption** — for new keys, push/email/PDF texts and `not-in-source` findings, confirm which loader
   reads which file and what an empty value renders ([consumption-and-fallback.md](references/consumption-and-fallback.md)).
   Test the loader in one line when possible; do not assume fallback.
5. **Content** — `scripts/dump_side_by_side.py --base … --head … [--langs] [--rewritten-only] [--grep]`.
   Read German in full and 2–3 more languages; for term shifts, grep the new term with the old gender's
   markers. Big PRs: spawn `language-reviewer` per language family in parallel.
6. **Locale formats** — any number, date, time, currency, percent or unit inside a string is checked
   against [locale-formats.md](references/locale-formats.md) (CLDR, generated by `scripts/locale_facts.py`).
7. **Verify each finding** before reporting: re-read the exact string at the head ref, check it is NEW,
   and drop false positives (inflected brands in fi, localized acronyms, legit spelled-out numbers).
8. **Report** with [report-template.md](references/report-template.md): verdict, blocking, fix-in-TMS,
   minor, OLD context, next steps. Publish an artifact if asked. **Draft** PR/Jira comments; post only
   after explicit approval.

## Locales in Scope (default set)

en (source), de, it, nl, fr, pt (pt_PT), es (es_ES), fi, cs, nb, sv, da, el, pl, ar — plus formatting
variants de_AT/de_CH, it_CH, nl_BE, fr_BE/fr_CH, en_US, ar_AE/ar_SA/ar_EG. Facts that matter most:

| Group | Decimal / group | Short date | Notes |
| --- | --- | --- | --- |
| en_GB / en_US | `.` / `,` | `07/03/2026` / `3/7/26` | en_US 12-hour, week starts Sun |
| de, it, nl, es, da, el | `,` / `.` | de `07.03.26`, da `07.03.2026`, nl `07-03-2026`, it/es/el `/` | `25 %` in de/es/da; el 12-hour, `;` = `?` |
| fr, pt, fi, cs, nb, sv, pl | `,` / (N)NBSP | fr `07/03/2026`, sv `2026-03-07`, fi `7.3.2026`, cs `07.03.26`, pl `7.03.2026` | fr NBSP before `;:!?`; fi/da time `14.05` |
| de_CH, it_CH | `.` / `’` | `07.03.26` | apostrophe U+2019, not `'` |
| ar | `.`/`,` (ar_SA, ar_EG: `٫`/`٬`, Arabic-Indic digits) | `7‏/3‏/2026` | RTL, `؟ ، ؛`, 6 plural forms, 12-hour |

Plural forms: one/other for most; fr counts 0 as one; cs 3 (one/few/other); pl 3 (one/few/**many**);
ar 6. Full tables: [plurals.md](references/plurals.md). Per-language grammar, formality and punctuation:
[language-notes.md](references/language-notes.md).

## Review Checklist (short)

- [ ] Placeholders identical to the source string (names, count); none added, dropped, hard-coded
- [ ] JSON/PO valid, no duplicate keys, `.mo` recompiled, `msgfmt -c` clean, plural form counts
- [ ] No translated value emptied, removed, or turned lowercase/English vs base
- [ ] Every source plural present in every language; converter maps pl `many` correctly
- [ ] New keys are read by code from this catalog; empty values don't render blank
- [ ] No hard-coded numbers/dates/currency; digits with meaning unchanged
- [ ] Term swaps consistent, agreement intact, one term per concept per screen and across platforms
- [ ] Brands/units unchanged (case too); punctuation per language; RTL intact
- [ ] Counterpart branch PR has identical content; hand edits mirrored in the TMS

Full list: [review-checklist.md](references/review-checklist.md). Known failure patterns:
[common-issues.md](references/common-issues.md).

## Anti-Patterns

| Don't | Why |
| --- | --- |
| Compare a translation with the msgid/key | Keys aren't English; placeholder diffs vanish |
| Say "falls back to English" without checking the loader | python-i18n/i18next return `''` → blank UI/push |
| Fix strings by hand in non-source catalogs | Next TMS export reverts it; fix in the TMS |
| Trust a green checker as "content OK" | Grammar, wrong terms and same-screen inconsistency need reading |
| Flag fi `kinexuksessa` or pl `DO` as brand/acronym errors | Inflection and localized medical acronyms are correct |
| Report 300 INFO lines inline | Bury the 5 that matter; summarize INFO once |
| Write numbers/dates from memory | Use the CLDR tables or `locale_facts.py` |
| Post review comments unasked | Draft first; external posts need explicit approval |

## Communication Style

- Lead with the verdict and the blocking list; no preamble
- Each finding: key, language, source, current, effect, fix — in a table when there are several
- Bullets and tables over paragraphs; quote strings exactly
- State how non-obvious claims were verified; mark unverified ones "confirm with native reviewer"
- No hedging on mechanical errors; no apologies

## Sub-Agent Delegation

| Agent | Role | Spawn When | Tools |
| --- | --- | --- | --- |
| [language-reviewer](agents/language-reviewer.md) | Content read for 1–4 languages from a side-by-side dump | >150 strings/lang or >5 languages; term shifts | Read Grep Glob |
| [consumption-auditor](agents/consumption-auditor.md) | Loader/fallback/dead-copy trace for keys | `not-in-source`, push/email/PDF keys, tooling or locale-dir changes | Read Grep Glob, read-only Bash |

### Delegation Rules

1. Generate the dump file first and pass its absolute path plus the relevant LEARNED.md entries
2. Sub-agents are read-only; only the parent writes reports, artifacts or LEARNED.md
3. Pass all context explicitly (paths, refs, languages, known findings); they can't see this conversation
4. Max depth 1; re-verify every sub-agent finding at the head ref before reporting it

## Freedom Levels

| Level | Scope | Examples (with WHY) |
| --- | --- | --- |
| **MUST** | Source-string comparison, NEW/OLD tags, loader check before "harmless", verify before report, draft-before-post, LEARNED.md writes | "MUST test the loader — an empty push went out blank" |
| **SHOULD** | Run both checkers, German in full, artifact structure, delegation thresholds | "SHOULD read German fully — most reviewable, catches source bugs" |
| **CAN** | Language sample beyond German, report format details, `--keep` list | "CAN skip ar content read if no Arabic reviewer — still run RTL checks" |

## Session Protocols

| Mode | Detection Signal | Behavior |
| --- | --- | --- |
| Full review | "review PR …", "find all issues" | Workflow 1–8, report + optional artifact |
| Quick check | "does this PR break anything", "run the checker" | Steps 1–2, ERRORs only |
| Diagnostic | "shows English/braces/blank in X" | Step 4 first: loader, served dir, value at head, then placeholder |
| Parity | "backport", "same as master?" | Diff catalogs and tooling between the two refs |

**Self-learning (write, don't suggest):** user corrects a finding or severity → restate as a rule, write to
`## Corrections`. New project fact (paths, served languages, glossary decision, brand) → `## Discovered
Conventions` with `[repo]` prefix. Stated preference → `## Preferences`. Format `- YYYY-MM-DD: rule`.
